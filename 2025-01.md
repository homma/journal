### rust の mod と use について
> date: 2025-01-13  
> topics: rust, module, namespace

`mod` も `use` も名前空間に作用するため、違いが分かりにくかった  

`mod` はモジュールを読み込み、モジュール名でアクセス可能にする  
`use` は名前空間のパスに別名を付け、作成した別名でアクセス可能にする  

#### 参考資料
- https://doc.rust-lang.org/reference/items/use-declarations.html

### rust の mod について
> date: 2025-01-13  
> topics: rust, module

#### 課題
`mod` はモジュールの定義と読み込みの両方に使われており、動作が分かりづらいと感じていた

#### 過去の認識
モジュールを定義する `mod`
````rust
mod mymod {

}
````

モジュールを読み込む `mod`
````rust
// mymod.rs をモジュールとして読み込む
mod mymod;
````

#### 現在の理解
両方とも、モジュールを定義して読み込んでいると考えると理解しやすい  

前者の形式 (`mod mymod {}`) はその場でモジュールを定義し、定義したモジュールを現在のコンテクストに読み込んでいる  

後者の形式 (`mod mymod;`) は外部ファイルにモジュールを定義し、定義されたモジュールを現在のコンテクストに読み込んでいる  

どちらもモジュールを定義し、読み込んでいる  
定義している場所がその場なのか、外部ファイルなのかが異なっている  

#### 例

以下のファイルが存在していたとする  

````
main.rs
mymod.rs
````

`mymod.rs` は自動的にモジュールになる  
`mymod.rs` ファイル内で `mod` キーワードを使用する必要はない

`main.rs` からは `mod mymod;` で `mymod.rs` をモジュールとして読み込める
`mymod.rs` 内の定義には `mymod::` でアクセスできる

#### 参考資料
- https://doc.rust-lang.org/reference/items/modules.html

### bindgen を試す rev.2
> date: 2025-01-13  
> topics: rust, bindgen  

#### 概要

ライブラリクレート (`lib.rs`) を作成せず、モジュールのファイルで bindings を読み込み、バイナリクレート (`main.rs`) から読み込んでみます  

ライブラリクレートを使用するとテストを実装・実行することができます  
一方、ライブラリクレートを使用しない場合は、構成がシンプルになります  

#### 生成された bindings を利用するプログラムの作成

````console
$ vi src/raylib.rs
$ vi src/main.rs
````

生成した bindings を `raylib.rs` ファイルのモジュールから読み込みます  

src/raylib.rs
````rust
#![allow(non_upper_case_globals)]
#![allow(non_camel_case_types)]
#![allow(non_snake_case)]
#![allow(unused)]

include!(concat!(env!("OUT_DIR"), "/bindings.rs"));
````

`main.rs` から `raylib.rs` を読み込み、使用します  

src/main.rs
````rust
mod raylib;

fn update() {
    unsafe {
        raylib::BeginDrawing();
        raylib::EndDrawing();
    }
}

fn main() {
    unsafe {
        raylib::InitWindow(600, 400, c"My Raylib Window".as_ptr());

        while raylib::WindowShouldClose() == false {
            update();
        }

        raylib::CloseWindow();
    }
}
````

### bindgen を試す
> date: 2025-01-13  
> topics: rust, bindgen  

#### 概要

Rust のプログラムで `bindgen` を使用して C のライブラリを利用してみます  

#### 準備

`cargo new` コマンドで Rust のプロジェクトを作成  
`cardo add` コマンドで `build-dependencies` に `bindgen` を追加  

````console
$ cargo new bgen_test
$ cd bgen_test
$ cargo add --build bindgen
````

#### bindings 生成用のファイル作成

C ライブラリのヘッダーファイルを参照するための `wrapper.h` と `bindgen` を実行する `build.rs` を作成します  
`wrapper.h` と `build.rs` はパッケージ直下（今回の場合は `bgen_test` ディレクトリ直下）に配置します  

##### `wrapper.h`

`wrapper.h` に bindings を生成するためのインクルードを記載  
今回は Raylib の bindings を生成します  

````console
$ vi wrapper.h
````

wrapper.h
````c
#include <raylib.h>
#include <raymath.h>
#include <rlgl.h>
````

##### `build.rs`

`build.rs` に `bindgen` を実行する処理を記載  
Raylib は Homebrew でインストールしたため、`brew --prefix raylib` コマンドでパスを検索しています  

````console
$ vi build.rs
````

build.rs
````rust
use std::env;
use std::path::PathBuf;
use std::process::Command;

struct BrewLib {
    pkg_name: String,
    lib_path: String,
    include_path: String,
}

impl BrewLib {
    fn new(pkg_name: String) -> Self {
        // search the base path
        let out = Command::new("brew")
            .args(["--prefix", &pkg_name])
            .output()
            .expect("faild to run brew.");
        let out = String::from_utf8(out.stdout).unwrap();
        let base_path = out.trim();

        // make the library path
        let lib_path = base_path.to_string() + "/lib";

        // make the include path
        let include_path = base_path.to_string() + "/include";

        BrewLib {
            pkg_name,
            lib_path,
            include_path,
        }
    }
}

fn main() {
    let pkg = "raylib";
    let raylib = BrewLib::new(String::from(pkg));

    // set library path
    println!("cargo:rustc-link-search={}", raylib.lib_path);

    // add library to link
    println!("cargo:rustc-link-lib={}", raylib.pkg_name);

    // generate bindings
    let include_option = String::from("-I") + &raylib.include_path;
    let bindings = bindgen::Builder::default()
        .header("wrapper.h")
        .clang_arg(include_option)
        .parse_callbacks(Box::new(bindgen::CargoCallbacks::new()))
        .generate()
        .expect("failed to run bindgen.");

    // write to a file
    let out_path = PathBuf::from(env::var("OUT_DIR").unwrap());
    bindings
        .write_to_file(out_path.join("bindings.rs"))
        .expect("cannot write bindings");
}
````

#### bindings の生成

`cargo build` コマンドで `build.rs` を実行し、bindings を生成します  

````console
$ cargo build
````

#### 生成された bindings を利用するプログラムの作成

````console
$ vi src/lib.rs
$ vi src/main.rs
````

生成した bindings はライブラリクレート (lib.rs) 内のモジュールとして読み込みます  

src/lib.rs
````rust
#![allow(non_upper_case_globals)]
#![allow(non_camel_case_types)]
#![allow(non_snake_case)]

pub mod raylib {
    include!(concat!(env!("OUT_DIR"), "/bindings.rs"));
}
````

バイナリクレート (main.rs) からライブラリクレート (lib.rs) のモジュール (raylib) を読み込み、使用します  

src/main.rs
````rust
use bgen_test::raylib;

fn update() {
    unsafe {
        raylib::BeginDrawing();
        raylib::EndDrawing();
    }
}

fn main() {
    unsafe {
        raylib::InitWindow(600, 400, c"My Raylib Window".as_ptr());

        while raylib::WindowShouldClose() == false {
            update();
        }

        raylib::CloseWindow();
    }
}
````

#### プログラムの実行

````console
$ cargo run
````

### Rust プログラムからコマンドを実行する
> date: 2025-01-13  
> topics: rust, homebrew  

`std::process::Command` を使用してコマンドを実行します  

````rust
use std::process::Command;

fn main() {
    let pkg = "raylib";
    let out = Command::new("brew")
        .args(["--prefix", pkg])
        .output()
        .expect("faild to excute brew command.");
    println!("{}/lib", String::from_utf8(out.stdout).unwrap().trim());
}
````

#### 参考資料
- https://doc.rust-lang.org/std/process/struct.Command.html
